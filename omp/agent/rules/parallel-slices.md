# 并行切片

适用范围：任何"要做的事不止一步"的任务（多文件改动、调研、批量核对、长清单审查）。

1. **先切再动手。** 开工时用 todo 列出切片，每个切片标清：要改的文件/目录（**独占写面**，不许两个切片写同一处）、能自己跑出读数的验收命令、明确不做什么。
2. **能并行就一次发完。** 互不依赖的切片用**一次** `task` 批量下发（一个 `tasks[]` 里放多条），不要一个一个来。子代理是空白上下文：每条任务自带目标、非目标、要读的文件、验收命令；别指望它读过你的会话。
3. **只串行依赖链。** 真正有顺序依赖的步骤才自己按顺序做。能并行却自己串行做，按缺陷处理——它把 wall time 换成 token 却一点没省。
4. **整合有 owner。** 有并发写者时指定一个收口人（子代理只回结论/补丁，不各自提交）；同一 checkout 上的并发写先隔离或分 worktree。
5. **记并行度。** 收尾时记下这次用了几个子代理、主会话几轮、上下文峰值——没有读数就不知道有没有变快。
